# Feedback — what designers met while designing with the skill

Each locked design sends a retro here as a pull request (`skill/qa/retro.mjs`, SKILL.md → THE FLOW,
step 6): what was asked, the decisions at each stop, where the skill got in the way, and what the
QA measured (how many runs, what failed most). Its proposed components go to
`storybook/proposed/<feature>/`, shown under "Proposed" in the Storybook.

**Triage:** read the PR, fix the skill where it got in the way (a doc, a QA check, the runtime, the
kit), and merge the retro once the fix is in, linking the fix's PR. The retros are public: they
describe the skill, not the product.
