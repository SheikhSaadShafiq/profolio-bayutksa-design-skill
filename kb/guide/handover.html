Handover — running this on your own machine

Everything this project knows is in two repositories and one rule: no value is written that was not measured from a render. The design system is generated from the Profolio codebase and from the product running in a headless browser; nothing in it is typed by hand, and every claim has a check that fails when it stops being true.

The two repositories

repowhat it is
chaudhary-umair-ahmad/profolio-bayutksa-design-skill This one. The design system, the pages, the knowledge base and all the tooling. Branch main.
SectorLabs/profolio-reactjs The product. Read, never modified — except for one route this project adds, which is kept here as a patch.

They must sit side by side. Every script defaults to ../profolio-reactjs, and the harness reads PROFOLIO_REPO if you keep them somewhere else.

Setting up

git clone https://github.com/chaudhary-umair-ahmad/profolio-bayutksa-design-skill
git clone https://github.com/SectorLabs/profolio-reactjs

cd profolio-bayutksa-design-skill
npm install

# the capture route: two new files and two registrations in the product
git -C ../profolio-reactjs apply ../profolio-bayutksa-design-skill/product-route/design-capture.patch

# stand the product up: rewrites yarn.lock's private mirror to public npm,
# stubs the one genuinely private package, installs, and refuses to finish if
# the installed antd, react or styled-components differ from the lockfile
node harness/install.mjs

npm run all

npm run all reads the product, renders it, builds every page, cuts the design system out of the stylesheet and runs every check. It stops on the first failure.

What you need that is not in git

  • Playwright with Chromium — the harness drives a real browser. It is the only way heights, stroke widths and row heights are known.
  • Nothing else. No API keys, no VPN, no account. The product is answered entirely from harness/fixtures.mjs.

What is built

  • deliverables/design-system.html — 38 components in atoms · molecules · organisms, self-contained, each with its states, what it is made of, where it is used and the exact CSS to lift.
  • deliverables/ — eleven page HTMLs, plus profolio-ksa.html which carries all of them in one file.
  • deliverables/components/ — one liftable file per component.
  • kb/ — 358 HTML pages: the product's screens, flags, copy, tokens and components, for an agent to read a little of rather than all of.
  • data/live/ — the product's own measurements. These carry geometry and class names and no text, href, src, value or id; scripts/leaks.mjs re-proves it before anything is written.

Known wrong, and worth fixing in this order

  1. The product checkout moved. Everything above was measured against a snapshot; the real SectorLabs/profolio-reactjs differs in 357 files under src/, with whole features added. Re-run npm run all against the real repo and expect numbers to move. Nothing is trustworthy until that has been done once.
  2. The dashboard draws 120 controls the product does not. scripts/pages/dashboard-body.html is the last hand-written page body and was written against a stale capture. It should go through a generator like the other ten.
  3. Four bodies sit at 41–48% of the product's node count — Reports ×3 and LMS Leads — and Ad License renders one card where the product renders four.
  4. 228 pf- classes are in no catalogue section — the whole settings and reports vocabulary. They cannot be cut into components or checked until they are catalogued in deliverables/components.html.
  5. The Listings range calendar is fabricated — both months share one invented day grid. The two date fields that would use it are deliberately inert.

The two habits that matter

Measure, then write. Every wrong value in this project came from taking one sample and promoting it to a rule — five row actions because the fixture listing offered no discount, a disabled upgrade circle because the account had no credits, a profile header built from a redirect that was never the profile page. When a page needs rebuilding, run outline.mjs against its capture and read the geometry.

A check per claim. There are 37 scripts and most of them exist because something was wrong and nobody noticed: check-captures.mjs because eight reference captures were a week stale, qa-components.mjs because cutting CSS by class name silently dropped rules, sync.mjs because a regenerated sprite never reached the pages embedding it. When you fix something, ask what would have caught it, and add that too.

Gotchas that cost real time

  • A capture older than the fixture lies quietly. It renders, so it looks fine, and it scores every page built against it as wrong in a region that is actually right. check-captures.mjs now names any capture whose header disagrees with the newest one.
  • Coverage over 100% means the reference is empty, not that the page is more than complete.
  • .pf-card is a flex column, so any row inside a card has to restate flex-direction:row.
  • The riyal mark U+FDFC is an Arabic letter, so the digits after it join one right-to-left run and the price renders backwards. CSS cannot fix it; the mark needs its own <bdi>.
  • antd's Badge clamps at 99, and its offset is w/2 - 14 — a width-dependent position, not a fixed inset.
  • Never read canvas/*.dc.html into an agent's context. Three files, about 92,000 tokens. Everything needed from them is already in kb/design/components/.
